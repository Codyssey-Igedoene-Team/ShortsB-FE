# 책 데이터 수신 준비

현재 화면·추천·독서 기록은 기존 로컬 카탈로그를 그대로 사용합니다. 서버 요청이나 자동 전환은 추가하지 않았습니다.

R4 명세를 받은 뒤의 실제 경로·타입·연결 차이는 [R4 API 연결 준비](api-integration-r4.md)에 정리했습니다. 아래는 로컬 데이터 접근 구조이며, R4에는 목록 API가 없고 본문 조회에도 독서 세션이 필요하므로 이 인터페이스를 서버에 그대로 대응시키지 않습니다.

## 준비된 코드

- `src/services/bookSource.ts`: 비동기 도서 목록·상세·본문 조회 인터페이스와 로컬 구현.
- `src/hooks/useBookData.ts`: 목록·상세·본문을 화면에 연결할 훅. 로딩, 빈 결과, 오류, 재시도를 구분하고 이전 요청을 취소합니다.
- `BookSummary`, `BookDetails`, `BookPageData`: 프론트에서 사용할 데이터 형식입니다. 서버 응답 형식을 정한 것이 아닙니다.

목록은 빈 배열이면 검색 결과 없음, 상세·본문은 `null`이면 해당 데이터 없음입니다. 통신 실패는 예외로 전달해 오류·재시도 안내로 처리합니다. 취소 신호는 실제 API 구현에서 fetch에 전달합니다.

## API 명세를 받으면 할 일

1. 실제 주소·인증·페이지네이션 규격에 따라 `BookSource`를 구현합니다. 서버 응답을 위 표시 모델로 변환하고 필수값을 검증합니다. 현재는 주소나 응답 키를 가정한 HTTP 코드를 작성하지 않았습니다.
2. 화면에서 해당 구현을 `useBooks(source)`, `useBookDetails(bookId, source)`, `useBookPage({ bookId, edition, index }, source)`에 전달합니다. 각 훅의 `status`, `data`, `error`, `retry`로 화면을 구성합니다.
3. 검색 화면만 먼저 바꾸고 끝내지 않습니다. 현재 추천·본문·진행률·기록은 로컬 `catalog.ts`의 책 ID와 카탈로그를 참조하므로, 서버의 책이 상세·독서·기록까지 같은 ID로 이어지도록 함께 연결해야 합니다.
4. 표지는 `coverUrl`로 받을 수 있도록 모델을 준비했습니다. 실제 표지 표시와 로딩 실패 대체 표지는 응답 규격 확정 후 `BookCover`에 연결합니다.

## 연결 전에 확인할 기준

- 책 ID와 판본 ID는 문자열로 유지합니다. 서버 ID가 큰 정수라면 서버에서도 문자열로 전송해야 정밀도가 손실되지 않습니다.
- 내부 페이지 위치 `index`는 0부터 시작합니다. 화면의 1페이지는 `index: 0`입니다. 서버 구간 번호와의 대응은 실제 명세에 맞춰 변환해야 합니다.
- 판본이 다르면 이전 페이지 위치와 형광펜을 새 본문에 그대로 적용하지 않습니다. 로컬 구현도 다른 판본의 본문 요청에는 `null`을 반환합니다.
- 목록·상세 정보에 전체 본문이 포함됐다고 가정하지 않습니다. 본문은 별도로 요청하도록 나눴습니다.
- 독서 기록 저장·추천 API·사용 권한 확인은 이번 준비 범위에 포함되지 않습니다.
