# shortB React 프론트엔드

기존 HTML 시안의 디자인과 기능을 React + TypeScript 컴포넌트로 옮긴 개발 프로젝트입니다. 개발 서버는 Vite를 사용하며, 동일한 React 소스에서 팀 검토용 개별 HTML도 생성합니다.

## 실행

Node.js 22.12 이상에서 프로젝트 폴더를 열고 실행합니다.

```sh
npm ci
npm run dev
```

터미널에 표시된 로컬 주소로 접속합니다. 기본 주소는 `http://localhost:5173/`입니다.

```sh
npm test         # 독서·기록·추천·저장·로그인·화면 전환 테스트
npm run build    # TypeScript 검사 후 dist/ 생성
npm run preview  # 생성된 결과 확인
```

- `/`: 로그인 상태면 홈, 비로그인 상태면 첫 독서 체험·계정 안내
- `/home`: 오늘 읽기 (로그인 필요)
- `/book?book=waiting`: 특정 책 상세
- `/reader?book=waiting`: 특정 책 읽기
- `/complete?book=waiting`: 독서 완료
- 빌드 후 `/pages.html`: 20개 화면의 전체 목록

화면을 이동할 때는 React 상태와 History API를 사용하며 주소에 `.html`을 붙이지 않습니다. 기존 `.html` 링크도 열 수 있으며 앱이 시작되면 확장자 없는 주소로 정리합니다. Vite 개발 서버와 `npm run preview`는 직접 접속과 새로고침을 지원합니다. 다른 서버에 배포할 때는 `/complete`처럼 실제 파일이 없는 경로에 `index.html`을 반환하는 SPA fallback 설정이 필요합니다. 빌드의 개별 HTML은 검토용으로 유지합니다.

## 구조

```text
src/
  App.tsx                    # Provider, Layout, Router 조합
  app/
    PageRouter.tsx           # 20개 경로 → React 페이지 컴포넌트
    routes.ts                # 주소 해석, URL 생성, 첫 방문 흐름
  layouts/AppLayout.tsx      # 헤더, 하단 메뉴, 알림, 본문 틀
  pages/                     # 독서·검색·책장·계정 등 화면
  components/                # 책 표지, 목표, 버튼, 공통 UI
  hooks/                     # 첫 체험 흐름, 실제 독서 시간 측정
  state/AppContext.tsx       # 앱 상태와 독서 액션 연결
  domain/                    # 추천, 페이지 진행, 기록, 저장 복원
  data/                      # 책 본문·출처·추천 관계·표지
scripts/                     # 본문 검증/가져오기, HTML 생성
content-source/              # 재빌드 가능한 원문과 완성 번역 스냅샷
public/fonts/                # 로컬 글꼴과 라이선스
```

페이지별 JSX와 상태가 실제 React로 구현되어 있습니다. 본문/입력값을 HTML 문자열로 합쳐 화면 전체를 교체하지 않습니다. 표지의 고정 SVG 도형만 검증된 로컬 데이터로 삽입합니다.

## 화면 분리 기준

**사용자가 수행하는 기능과 화면 전환 흐름**을 기준으로 나눕니다. 책마다 HTML이나 컴포넌트를 복제하지 않고 책 ID로 데이터를 바꿉니다. 추천 설정 3단계는 한 컴포넌트의 단계 상태로 처리합니다.

| 분류 | 경로 |
| --- | --- |
| 진입·독서 | index, trial, trial-done, home, book, reader, complete, discover |
| 추천·탐색 | setup, preferences, search |
| 기록 | library, calendar, highlights, goals |
| 계정 | login, signup (OAuth 로그인·가입) |
| 기타 | settings, source, about |

## 유지한 기능과 검증

- 오늘 목표: 하루 1·3·5·10페이지 중 선택, 읽기 버튼 아래 읽은 양·남은 분량·진행선
- 첫 목표 설정과 목표 변경은 같은 하루 목표를 사용합니다. 별도의 분량 선택 없이 오늘 읽은 페이지를 뺀 남은 목표만큼 읽고, 책 끝에서는 남은 페이지까지만 배정합니다. 목표 달성 후에도 계속 읽을 수 있습니다.
- 첫 설정 이후에는 한국 시간 기준 매일 첫 접속에 오늘 목표 페이지만 선택합니다. 학생·취향 설정은 반복하지 않습니다. 오늘 목표를 저장한 날짜를 별도로 보관하므로 같은 날 재로그인·새로고침에는 다시 묻지 않으며, 자정이 지나거나 다음 날 창으로 돌아오면 오늘 목표 화면으로 이동합니다. 지난 목표와 독서 기록은 유지합니다.
- 이어읽기: 현재 판본·책·페이지·스크롤 위치로 복원
- 같은 책/같은 날 같은 페이지 중복 집계 방지
- 가나다순 검색, 형광펜, 대비 추천의 되돌아가는 순환 방지
- 비로그인 상태에서 첫 체험 완료 후 새로고침해도 계정 안내 유지
- 지정 데모 계정 로그인 시 바로 홈, 재방문 시 로그인 유지, 설정에서 로그아웃
- 비로그인 상태에서는 회원 메뉴 접근 차단, 로그인 안내를 거절하면 본문 계속 읽기
- 게스트와 로그인 사용자 모두 독서 완료 → 다른 관점 추천 → 비교 설명 → 추천 대목 읽기 연결
- 이전 판본 기록은 보관하고 새 한국어 판본에 옛 페이지 번호를 적용하지 않음
- 발표용 달력은 실제 기록과 분리

로그인 여부에 따른 진입·저장 복원과 기존 독서 흐름은 자동 테스트로 검증합니다. 상세 구조와 로그인 구현은 [프로젝트 분석](docs/project-analysis.md)을 참고하세요.

## 백엔드 연결 범위

책 데이터 수신용 인터페이스와 로딩·오류·재시도 훅은 준비되어 있습니다. 아직 화면을 서버 데이터로 전환하거나 자동 요청하지 않습니다. 연결 지점과 미확정 기준은 [책 데이터 수신 준비](docs/book-data-preparation.md)를 참고하세요.

제공받은 OpenAPI R4의 추천·대비·도서·전체 독서 경로에 맞춘 호출 함수와 요청·응답 타입도 준비했습니다. 아직 실제 화면에는 연결하지 않았습니다. 명세의 숫자 타입 불일치와 전체 독서 상태 전환 기준은 [R4 연결 준비](docs/api-integration-r4.md)를 참고하세요.

Google 버튼을 누르면 백엔드의 `/oauth2/authorization/google`로 브라우저를 이동시킵니다. 사용자가 시작한 OAuth 흐름에서 돌아왔을 때만 쿠키를 포함한 `GET /api/me`로 로그인 상태를 확인합니다. 일반 실행·새로고침·창 복귀에서는 인증 서버를 자동 호출하지 않습니다. 로컬 저장된 로그인 값으로 서버 인증을 만들지 않습니다. 실제 서버 로그아웃은 `GET /api/csrf`에서 받은 토큰을 헤더에 담아 `POST /api/logout`으로 요청합니다. 통신 코드는 `src/services/authApi.ts`에 있습니다.

인증은 OAuth 로그인만 지원합니다. 이메일·비밀번호 입력, 이메일 가입·인증번호·비밀번호 찾기 흐름은 사용하지 않습니다. 현재 Google만 실제 인증에 연결되어 있고, 카카오·Apple은 준비 중으로 표시합니다. 책·목표·독서 기록·추천은 아직 로컬 구현입니다. `/api/me`에 첫 설정 완료 여부가 없으므로, 첫 설정 상태는 서버에서 확인한 사용자 ID별로 이 브라우저에 보관합니다.

### 로컬 연결

`npm run dev`만 실행해도 로그인 없이 체험 독서를 시작할 수 있습니다. 서버 자동 연결은 없습니다. 로그인 화면의 **테스트 로그인**은 개발 서버에서만 표시하며, 백엔드 없이 목표 설정과 회원 화면을 확인할 수 있습니다. 테스트 사용자는 실제 Google 사용자와 별도로 저장되고 같은 탭에서 새로고침해도 유지됩니다. 테스트 로그아웃·첫 설정 재시작·기록 복원도 서버를 호출하지 않습니다. 운영 빌드에는 테스트 로그인 버튼을 제공하지 않습니다.

1. `.env.example`을 `.env.local`로 복사하고 `VITE_API_BASE_URL`에 백엔드 주소를 넣습니다. 기본값은 `http://localhost:8080`입니다.
2. `npm run dev` 후 브라우저에서 `http://localhost:5173`을 엽니다. 백엔드와 프론트에서 `localhost`와 `127.0.0.1`을 섞지 않습니다. 실제 사용 포트가 다르면 아래 주소도 맞춥니다.
3. 백엔드 실행 환경의 CORS 허용 출처가 `http://localhost:5173`, 로그인 성공 이동 주소가 `http://localhost:5173/`, 실패 이동 주소가 `http://localhost:5173/login?error=google`인지 확인합니다. 이 작업에서 백엔드 파일은 수정하지 않았습니다.
4. 로컬 백엔드는 `local` 프로필과 HTTP에 맞는 쿠키 설정으로 실행되어 있어야 합니다. 운영에서는 HTTPS·배포 도메인에 맞는 CORS 및 쿠키 설정이 필요합니다.

`VITE_` 값은 브라우저에 공개됩니다. Google client secret이나 DB 비밀번호를 넣지 않습니다. `npm run build`도 같은 API 주소를 읽으므로 배포 주소를 변경하면 다시 빌드합니다. 쿠키는 브라우저가 관리하며 프론트에서는 세션 ID를 직접 읽거나 저장하지 않습니다.

독서/취향 데이터는 해당 출처(origin)의 로컬 저장소에 보관됩니다. 서버 주소나 포트가 바뀌면 저장 영역이 달라집니다. 이전 시안 저장 키를 같은 출처에서 발견하면 새 키로 옮기며 원래 키는 덮어쓰지 않습니다.

로그아웃하면 회원 독서 기록은 서버에서 확인한 사용자 ID별로 보관하고, 현재 화면 상태는 첫 방문 상태로 초기화합니다. 같은 Google 계정으로 로그인하면 이 브라우저에 보관한 기록을 복원합니다. 다른 계정에는 해당 기록을 적용하지 않습니다. 설정의 첫 로그인 테스트는 실제 서버 로그아웃 후 시작하며, 백업 복원도 원래 Google 계정의 인증을 확인한 후에만 수행합니다.

## 본문과 번역

한국어 원문 2편 + AI 한국어 전문 번역 5편을 포함합니다. 다른 4편은 번역 중으로 본문이 열리지 않습니다. AI 번역은 전문 번역가 교열 전임을 출처 화면에 표시합니다.

기본 빌드는 저장소 안의 스냅샷만 사용합니다. 새 번역을 가져올 때만 아래처럼 경로를 지정합니다.

```sh
SHORTB_TRANSLATIONS=/path/to/translations npm run content
npm run build
```

원문 SHA, 전체 문단 순서, 빠진 문단, 원문 대조 검수 상태, 장 범위를 확인한 완성본만 반영합니다. 임의 요약이나 기존 출판 번역문으로 대체하지 않습니다.
